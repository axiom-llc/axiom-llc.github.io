AXIOM separates policy, execution, and context so each responsibility has an explicit interface and a testable operational boundary.

Core / 01—03

The execution path.

This is a responsibility map, not a claim that every deployment has the same threat model or operating envelope.

  1. 01Pre-execution

    ASON

    Policy enforcement

    Validates a caller-supplied plan against caller-supplied step limits, tool controls, and impact classification. An accepted tool sequence is translated and submitted to APEX without probabilistic replanning.

    Repository ↗
  2. 02Execution

    APEX

    Agentic Process Executor

    Accepts natural-language tasks or exact plans, validates tool schemas, records the accepted sequence, and executes within configured limits. Its durable ledger supports conservative recovery and replay; it does not establish exactly-once external effects.

    Repository ↗
  3. 03Context

    RAG

    Retrieval and storage

    Owns document ingestion, embedding-space identity, semantic retrieval, and grounded generation. A versioned HTTP boundary lets runtime consumers use storage without opening its persistent root directly.

    Repository ↗
Relationship

ASON governs submission to APEX. APEX executes the accepted plan. RAG is a context service reached through explicit adapters; it is not the policy or execution engine.
