Engineering

Explicit systems.
Inspectable behavior.

AXIOM favors narrow interfaces, deterministic control paths, local-first validation, and evidence that can be reproduced without a hidden platform.

Practice

Reliability is a boundary discipline.

01

Separate proposal from execution

Models may generate plans. Typed schemas, policy checks, active tool registries, and runtime limits determine what can execute.

02

Fail closed around uncertainty

Unknown tools, ambiguous recovery states, invalid storage identity, and absent authority stop work instead of being silently inferred.

03

Record before mutation

Where effects matter, durable intent and accepted-plan identity are established before dispatch so recovery can be conservative.

04

State the operating envelope

Process-crash tests do not prove host-power-loss behavior. Local integration does not imply a production deployment. Limits belong beside results.

Validation

Reproducibility over ceremony.

Evidence is kept close to the implementation and strengthened in proportion to the risk.

  1. 01

    Specify the invariant

    Name the interface, state transition, trust boundary, and failure semantics before expanding the implementation.

  2. 02

    Exercise the owning component

    Run repository tests, static checks, failure-path probes, and targeted integration checks with controlled inputs.

  3. 03

    Preserve the evidence

    Record relevant revisions, configurations, known exclusions, and the exact commands needed to reproduce a result.
